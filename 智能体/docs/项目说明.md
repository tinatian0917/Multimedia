# 项目说明（HR-20）

---

## 一句话介绍
把同一候选人多轮面试纪要拆成事实/评价/归纳三栏，每条归纳挂原文出处，产出待办清单——**不打分、不下录用建议、不猜填缺段**。

---

## 解决什么痛点
> 几轮面试下来，纪要散在不同面试官的文档里，汇总时容易把主观印象当成事实写进去，还常常漏掉"当时约定的下一步"。候选人问进展，谁也说不清。

| 痛点 | 本项目怎么解决 |
|------|---------------|
| 主观印象当事实 | 事实和评价严格分栏，事实栏只放原文直抄的客观内容 |
| 漏了"约定的下一步" | 自动扫描关键词提取待办，每条约占来源轮次+原文出处 |
| 瞎编缺段 | 缺段只标【待补】，绝不猜测填补 |
| 打分/录用建议混进交付物 | 护栏自动拦截，违规段落自动过滤，交付物里搜不到评分/录用关键词 |

---

## 怎么用（两条命令）

```bash
# 跑完整流程
python3 scripts/hr20.py --candidate "张三/Java后端/ID-20261117-003" --minute-dir demo/张三/

# 验证护栏（可选）
python3 scripts/verify.py --candidate "张三/Java后端/ID-20261117-003"
```

## 架构四层（一句话说清每层负责什么）

| 层 | 负责什么 | 不能做什么 |
|----|---------|-----------|
| **模型** | 语义判断（分栏/归纳/待办提取） | 不能直接读文件、不能写交付物、不能外发 |
| **Harness** | 3 阶段串行执行、状态管理、中断恢复 | 不能跳过护栏检查、不能绕过人工确认 |
| **工具（indexer）** | 只读文件、建段落索引、标记缺段/矛盾 | 不能修改原始文件、不能打分、不能做录用判断 |
| **沙箱** | 隔离所有产出物（索引/分栏/交付物/轨迹） | 不能访问外部网络、不能调用外部 API |

## 护栏铁律（7 条，违反即停）

1. 只做无损汇总，不许改原文（包括错别字、口语、标点）
2. 不许打分（任何形式的数字分/等级/星级）
3. 不许下录用建议（建议录用/淘汰/推荐终面等）
4. 事实和评价严格分栏（事实=原文直抄/评价=主观判断）
5. 归纳句每条 ≥ 2 条原文出处
6. 矛盾事实各自保留，不许合并
7. 缺段只标【待补】，不许猜测填补
